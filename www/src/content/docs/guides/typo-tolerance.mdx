Typo fallback is **opt-in on the definition** and still **capability-gated**
at search time.

```ts
typoTolerance: { mode: "fallback" }
```

Default is `{ mode: "off" }`. The only other accepted mode is `"fallback"`.

## What "fallback" means

1. The exact/prefix FTS5 query runs first.
2. SiftLite also retrieves bounded trigram candidates and scores them with
   Damerau-Levenshtein.
3. Fuzzy survivors that are not already exact matches are appended **behind**
   the exact/prefix group (1-edit before 2-edit). Exact hits are never
   displaced.

It is not always-on query rewriting into FTS5 `OR` fuzz. Empty-query
browsing does not enter this path.

## Requirements that all have to hold

- Definition `typoTolerance.mode === "fallback"`.
- Runtime probe `trigramTokenizer === true`.
- Search policy does not disable it.

Default search policy is
`typoFallback: "disabled-on-cost-sensitive-runtimes"`. D1 adapters set
`costSensitive: true`. If the definition requests fallback under that policy,
search throws `SEARCH_CAPABILITY_UNSUPPORTED` /
`typo-fallback-unsupported`; it does not run exact-only search. Keep the
definition mode `"off"` unless you pass an explicit policy that enables it
**and** accept the cost.

```ts
createFts5Engine({
  adapter: d1Adapter(env.DB),
  policy: { typoFallback: "enabled", costSensitive: true },
});
```

That combination is a deliberate policy decision. `D1_DEFAULT_SEARCH_POLICY`
rejects fallback-enabled definitions by default.

Bound scope and request `filter` are applied to fuzzy candidate retrieval.
`page.hasMore`, opt-in `totalHits`, and facets describe the merged
exact-plus-fuzzy set (exact matches and fuzzy-only survivors are disjoint).
Field sort applies to the exact group only. Fuzzy hits are ordered by edit
distance and `hit.score` is `null` — the public score is not the edit
distance. Highlighting is omitted on fuzzy hits; if a returned hit is fuzzy
and you requested highlight fields, the response includes warning
`highlight-unavailable-fuzzy`.

D1 still disables fallback by default until D1 remote cost evidence exists.
Local 100k/1m characterizations live in `docs/benchmarks/`.

## Bounds

Declared `DEFAULT_FUZZY_POLICY` values:

| Limit | Value |
| --- | --- |
| `minTokenCodepoints` | 3 |
| `maxQueryTokens` | 4 |
| `maxTrigramsPerToken` | 24 |
| `minGramOverlap` | 1 |
| `maxCandidates` | 200 |
| `maxEditDistance` | 2 |

`maxEditsForToken` further caps edits by token length. When fallback runs
and you pass `diagnostics: true`, `response.meta.fuzzyUsed` is `true`.

Candidate retrieval ORs generated grams, then enforces `minGramOverlap`
before edit-distance scoring. The effective candidate cap is
`min(DEFAULT_FUZZY_POLICY.maxCandidates, ApplicationLimits.maxFuzzyCandidates)`.
