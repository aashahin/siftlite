# v1.0 RC evidence pack

Date: **2026-08-21**

Published npm baseline remains `@siftlite/*@0.2.0`. This file records Phase 14
hardening evidence. **P14-10 (publish RC) stays owner-gated.**

## P14-01 Public API freeze

Authoritative surface is each package `src/index.ts` plus `bun run check-exports`.

| Package | Public role | Engines |
| --- | --- | --- |
| `@siftlite/core` | Types, planner, ASTs, codecs, scopes | Node >=20, Web/edge-safe |
| `@siftlite/fts5` | FTS5 backend + engine + lifecycle | Node >=20 |
| `@siftlite/bun` | `bun:sqlite` adapter | Bun >=1.2 |
| `@siftlite/d1` | Cloudflare D1 adapter | Node >=20 / Workers |
| `@siftlite/libsql` | libSQL / Turso Cloud FTS5 adapter | Node >=20 |
| `@siftlite/node` | better-sqlite3 adapter | Node >=20 |
| `@siftlite/testing` | Conformance / testkit | — |
| `@siftlite/drizzle` | Drizzle companion | drizzle-orm ^0.45.0 |
| `@siftlite/prisma` | Prisma companion | @prisma/client ^6 |
| `@siftlite/cli` | Noninteractive CLI | Node >=20 |

There is no umbrella `siftlite` package. Experimental Turso-native FTS is not
a published stable package.

Root export maps must keep `types`, `bun` (source), and `import`/`default`
(dist). Adding a new top-level export is an RC-breaking change.

## P14-07 Dogfood

Shared-tenant dogfood is `examples/d1-worker`: linked products index, required
`x-tenant-id` / `?tenant=`, `d1SessionAdapter` bookmarks. Complementary schemas:
`examples/bun-basic`, `examples/drizzle-bun`, `examples/libsql-basic`. Per-tenant
databases are an alternative isolation model; the D1 example documents why a
missing tenant must not browse every tenant.

## P14-08 Migration / recovery

`packages/fts5/tests/lifecycle.test.ts` applies companion SQL (pending registry)
then `createIndex` to mark healthy, and checks interrupted/leftover generation
cleanup. Public lifecycle docs match that path.

## P14-09 Secure-delete and backups

FTS5 `secure-delete` is opt-in (`required-if-supported`), version-gated, and
does not claim provider Time Travel / replica / backup erasure. D1 export
cannot dump FTS5 virtual tables; drop `__sift_*_fts` / `__sift_*_tri`, export
authoritative tables, rebuild after import.
