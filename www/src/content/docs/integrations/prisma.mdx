This package does **not** model FTS5 in `schema.prisma` and does **not**
use Prisma query hooks to synchronize indexes. `@prisma/client` is an
optional peer and is never required to compile the package. Supported
client family: Prisma 6 (`@prisma/client` ^6).

```ts
import { createPrismaSearch } from "@siftlite/prisma";

const productSearch = createPrismaSearch({
  prisma,
  adapter,
  model: "product",
  index: productsIndex,
});

const result = await productSearch.search("iphone", { hydrate: true });
```

When the Prisma field name differs from the SQL primary-key column (for
example `pid` mapped to `"id"`), pass `prismaIdField`. Hydration
`findMany` and `row[id]` use that field. Triggers and companion SQL still
use `index.source.primaryKey.field`.

## Companion SQL

```ts
import { generatePrismaSearchSql } from "@siftlite/prisma";

const migration = generatePrismaSearchSql(productsIndex);
```

The fragment is a deterministic **subsequent** Prisma migration. It never
rewrites previously applied migrations. The fragment creates physical objects
and a `pending` registry row. After applying it, run `createIndex` once with
the same definition to verify the objects and mark the row `healthy`, then
call `createPrismaSearch`. An intact pending generation is reused; incomplete
objects may be rematerialized during recovery. A later call against a healthy
row throws `SEARCH_CONFIG_INVALID` / `already-exists`.

In `0.1.0`, companion SQL does not emit the trigram table required by
`typoTolerance.mode: "fallback"`. Use runtime `createIndex` without applying
the fragment for those definitions.

## Client Extension

Ergonomic only. Close over the real Prisma client; `$extends` model
methods do not receive `{ client }` as `this`.

```ts
import { searchExtension } from "@siftlite/prisma";

const base = new PrismaClient();
const prisma = base.$extends(
  searchExtension({
    prisma: base,
    adapter,
    models: { product: productsIndex },
    prismaIdFields: { product: "pid" },
  }),
);
```

Portable source IDs remain `string | safe-integer`. BigInt and composite
IDs are rejected by core.
