`@siftlite/cli` works on Node 20+ and Bun.

<PackageManagers pkg="@siftlite/cli" dev />

```bash
npx --package=@siftlite/cli siftlite help
npx --package=@siftlite/cli siftlite version
npx --package=@siftlite/cli siftlite init
npx --package=@siftlite/cli siftlite generate --name products --table products --search title --json
```

After a local dev install, the shorter `npx siftlite ...` form uses the same
binary.

## Config

Operational commands load `siftlite.config.mjs` (or `--config <path>`). The
module must export:

- `createAdapter()` — returns a `SqlAdapter` (import `@siftlite/node`,
  `@siftlite/bun`, or `@siftlite/libsql` from host code)
- `indexes` — one definition, an array, or a record of definitions

Use `--name <index>` when more than one index is configured.

## Commands

| Command | Behavior |
| --- | --- |
| `help`, `version` | Prints help or package version |
| `init` | Scaffolds `siftlite.config.mjs` (`--force` to overwrite) |
| `generate` | Emits companion SQL (flag-based definition; typo fallback off) |
| `check`, `doctor` | Load config and run engine integrity / doctor reports |
| `backfill`, `rebuild`, `merge`, `drop` | Mutating lifecycle ops; require `--acknowledge` |

Global flags: `--config`, `--name`, `--json`, `--dry-run`, `--acknowledge`,
`--force`. There is no subcommand-help parser: `siftlite check --help` runs
`check` (and fails if no config is present).

## `generate`

Prints companion SQL for a linked index with one searchable column.
Defaults: `--name products`, `--table` equals name, `--search title`.

The generated SQL creates physical objects and a `pending` registry row. Run
`createIndex` once with the same definition to verify the objects and mark the
row `healthy`. The generated definition keeps typo fallback off, so it does
not require a trigram companion table. Fallback-enabled definitions should use
runtime `createIndex` or companion SQL that includes the trigram DDL.

## `check` and `doctor`

Require a resolvable config. They call `index.check()` / `index.doctor()` and
exit non-zero when error findings are present. `--json` prints the structured
`CliResult` including the report payload.

## Destructive commands

`drop`, `rebuild`, `backfill`, and `merge` require `--acknowledge` (unless
`--dry-run`, which prints the plan without executing). `drop` removes search
objects only and never drops the source table.
