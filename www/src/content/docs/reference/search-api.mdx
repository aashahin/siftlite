```ts
import { createFts5Engine } from "@siftlite/fts5";

const engine = createFts5Engine({ adapter });
const index = engine.index(definition);
```

Optional engine fields: `policy`, `limits`, `hooks`, `secureDelete`.

## `Fts5IndexHandle`

| Method | Notes |
| --- | --- |
| `search(query, request?)` | Parsed plain-text query |
| `searchRaw(raw, request?)` | `unsafeFts5Query(value)` only |
| `scope(values)` | Immutable AND of filterable equalities |
| `upsert(documents)` | Manual mode only |
| `delete(id)` | Manual mode only |
| `create()` `rebuild()` `drop()` | Lifecycle |
| `check()` `doctor()` | Registry / integrity |

`definition` is readable on the handle.

## `SearchRequest`

| Field | Type |
| --- | --- |
| `filter` | `FilterNode` |
| `sort` | `relevance()` / `asc` / `desc` |
| `facets` | configured facet names (filterable or sortable keys on typed handles) |
| `highlight` | searchable field names |
| `highlightMarkers` | `{ start, end, ellipsis }` |
| `limit` `offset` | pagination |
| `includeTotal` | opt-in exact count |
| `hydrate` | attach a projected document; ORM companions attach ORM rows |
| `diagnostics` | fill `response.meta` |
| `matchingStrategy` | override index default |
| `scope` | extra bound scope (still cannot strip handle scope) |
| `signal` | `{ aborted: boolean }` |

## `SearchResponse`

`hits`, `page { limit, offset, hasMore }`, `query`, `backend`. Optional:
`totalHits`, `estimatedTotalHits`, `facets`, `facetStats`,
`processingTimeMs`, `warnings`, `meta`.

`hit.score` is `number | null`. Empty-query browsing returns `null` when
no relevance is computed.

The generic engine's projected document contains the source ID plus declared
searchable, filterable, and sortable fields. It does not read every column
from a linked source table. Drizzle and Prisma search handles install their
own rank-preserving hydrators.

The low-level `searchFts5Index(ctx, query, request)` export requires a complete
`Fts5SearchContext`: adapter, definition, physical index ID, and generation.
Callers that resolve those values from `readRegistry` must also reject missing
or non-healthy rows before searching, as the engine and ORM companions do.
